# 样文库

把用户引用的材料整理成插件能用的东西。最后要有三个产物，缺一个都还用不起来：

| 产物 | 是什么 | 干什么 |
| --- | --- | --- |
| 库 | 一个名字 + 一批笔调标签 | 分类和挑选的单位 |
| 摘录 | 十几段逐字原文 | **证据**：让模型看见「长这样」 |
| 风格卡 | 九个维度的观察 + 基因/铁律/禁用 | **规则**：告诉模型「必须这样、绝不那样」 |

只有摘录时，模型看得见样子但不知道边界；只有卡时，规则清楚但少了具体的质感。**两个一起给才稳**——所以这是一个流程，不是两套体系。

```
定标签（停下来等用户）
   ↓
切段 · 打标签 · 批量入库
   ↓
提炼风格卡（问一句再动手）
   ↓
设成本局使用 · 告诉用户怎么看效果
```

## 前提：材料必须由用户引用

素材来自用户在「剧本与素材库」引用的材料，引用之后原文才在你上下文里。

**不要**读文件系统、不要找素材库目录、不要用 shell 翻文件——插件没有这类接口。

用户没引用材料时，先请他去引用，不要凭空编造摘录。

## 阶段一：定标签（必须停下来）

1. `style_library_list` —— 看现有库、条数、有没有卡。有内容相近的库就问用户是追加还是新建，别建一堆名字不同、内容重复的库。
2. 和用户定范围：一个库对应**一种笔调**或**一本书**。
3. **通读材料，替它拟一批笔调标签**（自动生成，不用等用户说）。数量看复杂度：

   | 材料情况 | 提议标签数 |
   | --- | --- |
   | 短篇、笔调统一 | 5～7 个 |
   | 中篇、笔调有起伏 | 8～12 个 |
   | 长篇、多种腔调混着 | 12～18 个 |

   标签只描述**笔调**（冷峻、留白、短句、燥热、文白、絮语…），不描述题材、人物、情节。池子里已有的合适标签直接复用，不要换个近义词重造一套。
4. `style_tags_update`（`action: 'add'`）加进池子，**把清单列给用户，明确请他增删改**。

   **这一步必须停下来等回复**。用户说「你看着办」「就这样」时才可以直接继续。
5. 用户改了照做：加用 `add`、删用 `remove`、改名用 `rename`（会自动同步库里已用的旧名字）。改完再确认一次最终清单。

## 阶段二：切段入库

6. `style_library_split` 把材料切开（面板「切段预览」同款规则）。切出来能直接用，但**笔调是否完整要你自己判断**：明显是一个完整场景就宁可超长别切断；一段里混了两种笔调就拆成两条。
7. **给每段定一个主标签**，从阶段一确认过的池子里选。按笔调归，不按情节归。
8. **按标签分组排序**：同一主标签的段落连续放，组内再按原文先后排。轮换时同类笔调连着出现，注入的参考风格才稳。
9. **算要摘几条**，别凭感觉少摘：

   | 材料字数 | 目标条数 |
   | --- | --- |
   | 1 千字以内 | 1～2 条 |
   | 1 千～5 千字 | 3～5 条 |
   | 5 千～1 万字 | 5～9 条 |
   | 1 万～2 万字 | 9～15 条 |
   | 2 万字以上 | 15～20 条（单库上限 40 条） |

   按「字数 ÷ 1500」估算是安全起点。**2 万字的文章只给一条是错的**——那等于把整篇压成一个样本，轮换也没得换。宁可多摘让用户删。
   材料超过 5 万字时不必硬凑满 40 条，优先覆盖**笔调变化最明显的位置**（开头定调、情绪转折、场景切换、结尾收束）。
10. **逐字摘录**：
    - 只摘**完整的段落或场景**，不摘句子碎片，也不摘整章。
    - 单条 200～2000 字。原文超长就选笔调最典型的几段。
    - **原文照抄**：不改标点、不改错别字、不删节、不概括、不补写。注入进去的是这段字的质感本身，改写就失去意义了。
    - **沿全文铺开**：开头、中段、后段都要有。长文里笔调会随情节漂移。
11. 用 `style_library_save` 建库（库标签取这批里最主要的 3～5 个），再用 **`style_sample_save_many` 按第 8 步的分组顺序一次存入全部摘录**。每条带主标签（可加 1～2 个次要，最多 5 个），`source` 填书名或章节。
12. **自查一遍**：材料 2 万字却只存了 1～3 条，就是没做完，回材料里继续摘。材料确实只有那么多可用完整段落（大量对话碎片、夹杂说明文）时，说清实际情况让用户决定。

## 阶段三：提炼风格卡

摘录存完，**先给用户看一眼结果**（库名、条数、按标签分组的情况），然后问一句要不要现在提炼卡。

> 摘录只是「有样子」。要让它稳定按这个笔调写，再把库提炼成一张风格卡——九个维度的观察、写作基因、铁律、禁用清单、AI 腔词表。现在就做吗？

用户说做（或本来就说「要复刻笔调」）就继续，否则收尾。

13. `style_card_get` 先看有没有旧卡。**有旧卡就做增量修订**，别整张重写——用户可能手改过，重写会冲掉。素材少于 3 条时不要提炼，直接说明原因（样本不够会把即兴当风格）。
14. **按九个维度落数**，标准见 `references/framework.md`：

    | key | 维度 | 量什么 |
    | --- | --- | --- |
    | `lexical` | 词汇 | 高频词、指纹词、固定搭配、用词质感 |
    | `syntactic` | 句法 | 平均句长、长短句分布、标点指纹、段落节奏 |
    | `tonal` | 语气 | 口语化程度、冷热、断言强弱、句长波动 |
    | `discourse` | 篇章 | 开头怎么起、场景怎么推进、在哪收 |
    | `rhetoric` | 修辞 | 比喻密度与取材、排比、设问、具体与抽象的比例 |
    | `emotion` | 情感 | 极性分布、情绪弧线、克制度 |
    | `perspective` | 视角 | 人称、聚焦方式、价值词 |
    | `imagery` | 感官 | 视觉/听觉/触觉的权重，有没有通感 |
    | `dialogue` | 对白 | 对白多长、有没有提示语、人物怎么区分 |

    每个维度 3～5 条、每条不超过 140 字。四条硬规则：

    - **出现 3 次以上才算特征。** 一次是即兴，三次才是风格。
    - **矛盾要保留。** 前后不一致的地方写进去，不要调和成一句四平八稳的总结。
    - **不猜。** 不写作者生平、写作意图，不把通用写作建议（「要具体」「要有冲突」）当成本书特征。
    - **不抄原文进卡。** 卡写的是规则和观察。

15. 合成四样东西：
    - **写作基因 3～5 条**：至少两个维度共同支撑、删掉就不像了的特征。4～6 字的名字 + 一句话说明它由哪几个维度撑起来。
    - **铁律 6～10 条**：落到操作层，写完回头看一眼就能判断有没有做到。反例「要生动」，正例「每段至少一个可以摸到的物件」。
    - **禁用清单 5～10 条**：这段文字**从不做**的事，具体到句式、词、动作。它比正面特征更能定边界。
    - **AI 腔词表**：这批文字里根本不会出现的套话（「不由得」「心中五味杂陈」这类），最多 20 个。
16. `style_card_save` 存进库，核对返回的 `counts`（维度数、基因数、铁律数、禁用数、AI 腔数），缺项就补。
17. **卡存完还没生效。** 问用户要哪种注入方式，然后 `style_library_save`（**记得把库里原有的 tags 读出来原样带回去**，这个接口会覆盖 tags 和 note）：

    | mode | 注入什么 | 什么时候用 |
    | --- | --- | --- |
    | `sample` | 只有一段摘录 | 默认。只想给样子 |
    | `both` | 规则 + 摘录 | 最稳，token 也最多 |
    | `card` | 只有卡 | 摘录会带偏剧情、但规则想要 |

18. 告诉用户：库名、条数、按标签分组的结果、卡里最关键的几条，以及**怎么验收**——面板「试写一段」或状态页看「下一轮样文笔调」。

## 阶段四：收尾

19. 用户要现在就玩，`style_library_pick` 设成本局使用。
20. 说明后续三个入口：状态页「下一轮样文笔调」看这一轮用什么、「换一段」换下一段、正文里写 `#文风 冷峻` 临时换。
21. 提醒**别同时开内置「文风联想」**——两边都往正文里放范文，会互相顶。

## 不必走完整流程的情形

用户只说要一件事时，直接做那件事，别硬拉一遍全流程：

| 用户说 | 做什么 |
| --- | --- |
| 「这几个标签加上／改个名」 | `style_tags_update` |
| 「再加几段摘录」 | `style_library_list` 拿 id → `style_sample_save_many` |
| 「重新提炼一下卡」 | `style_card_get` → 增量修订 → `style_card_save` → 提醒 mode |
| 「换成只用卡」 | `style_library_save` 传 `mode: 'card'`，tags 原样带回 |
| 「这个库太大了，拆成两个」 | 见下 |

## 拆库

总量是硬上限（Tavern 只给每个插件一份 256 KB 的 JSON），碰到容量就得拆。按笔调拆，不要按书拆——选库是按标签走的。

1. `style_library_save` 建新库，名字按笔调取（「冷峻打斗」比「下册」有用），标签沿用旧库那套。
2. `style_sample_move` 把要挪的段移过去。**移动会同时从原库删掉**，不要再用别的办法删一遍。
3. 新库缺卡：让用户在原库「导出 Prompt」→ 新库「粘贴一张卡」，零模型调用。或者你有材料就重新提炼一次。
4. **提醒用户一局可以选多个库**：`style_library_pick` 传 `libraries: ['冷峻打斗','冷峻抒情']`，两个库的摘录会合成一个池子轮换。否则他会以为拆完得来回切。

拆之前先算一下：一条 1500 字的中文摘录约 4.5 KB，总量 250 KB，所以「五六十条」就是天花板。单库别卡到 40 条，35 条左右就该开新库了——真顶到上限时保存会失败并让人删，那时候已经不好删了。

## 边界

- 用户的材料里没有的内容不要补。摘录必须能在材料里找到原句。
- 材料是写作教程、书评、分析类文章时，这类文字本身不构成「笔调样本」——它讲的是怎么写，不是写出来的样子。说清楚，问用户换材料。
- 材料是 JSON 或其他结构化数据时，先看清哪个字段是正文，只摘正文。
- 用户的标签判断和你的冲突时**听用户的**。标签是他的分类习惯，不是客观真理。
- 删摘录只能用面板（工具里没有批量删）。
