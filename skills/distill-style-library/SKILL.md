# 提炼风格卡

把样文库里已经存好的**原样摘录**，提炼成一张能照着写的**风格卡**。

摘录是证据，风格卡是规则。摘录告诉模型「长这样」，风格卡告诉模型「必须满足这些、永远不要出现那些」。两者一起注入时，模型既不容易跑偏，也不容易写成那种一眼是 AI 的调子。

分析框架见 `references/framework.md`（9 个维度、量化阈值、跨维度验证规则），叙事公式见 `references/formulas.md`。

## 什么时候用

- 用户说「把这个库提炼一下」「做个风格卡」「分析这本书的笔法」。
- 用户抱怨「照着摘录写还是不像」——多半是只有样本、没有规则。
- 库里已经存了 5 条以上摘录，用户准备长期用这个库。

**不要**在建库还没存够摘录时就提炼：少于 3 条时提炼出来的是「这几段的调子」，不是「这本书的调子」。先提醒用户补摘录（用 `create-style-library` 那套流程）。

## 前提：材料在库里

风格卡只能基于**库里已有的摘录**（`style_library_list` 能看到条数）。不要读文件系统、不要找素材库目录——插件没有这类接口。

用户引用了一整本书但还没建库时，先按 `create-style-library` 建库存摘录，再回来提炼。

## 流程

### 一、先看现状

1. `style_library_list`：确认目标库存在、有多少条摘录。
2. `style_card_get`：看有没有旧卡。**有旧卡就做增量修订**，不要整张重写——用户可能已经手改过其中几条，重写会把它冲掉。

### 二、读摘录，按 9 个维度落数

读库里每条摘录的原文（`style_card_get` 给的是卡，不是原文；原文要靠 `style_library_list` 里看到的条数配合用户在面板里查看，或直接让用户把要分析的那几段贴给你）。

**分析必须落数。**「喜欢用短句」没有信息量；「平均 11 字，七成句子在 8 字以内」才有。每个维度 3～5 条，每条不超过 140 字。

| 维度 | key | 量什么 |
| --- | --- | --- |
| 词汇 | `lexical` | 高频词、指纹词（明显高于一般文本的）、固定搭配、用词质感 |
| 句法 | `syntactic` | 平均句长、长短句分布、标点指纹（破折号/省略号/感叹号）、段落节奏 |
| 语气 | `tonal` | 口语化程度、冷热、断言强弱、句长波动 |
| 篇章 | `discourse` | 开头怎么起、场景怎么推进、在哪收 |
| 修辞 | `rhetoric` | 比喻密度与取材（从哪个领域取喻）、排比、设问、具体与抽象的比例 |
| 情感 | `emotion` | 极性分布、情绪弧线、克制度 |
| 视角 | `perspective` | 人称、聚焦方式、价值词 |
| 感官 | `imagery` | 视觉/听觉/触觉各占多少，有没有通感 |
| 对白 | `dialogue` | 对白多长、有没有提示语、不同人说话怎么区分 |

三条硬规则：

- **出现 3 次以上才算特征。** 一次是即兴，三次才是风格。
- **矛盾要保留。** 前后不一致的地方写进去，不要调和成一句四平八稳的总结。
- **不猜。** 不写作者生平、写作意图，不把通用写作建议（「要具体」「要有冲突」）当成本书特征。

### 三、合成

1. **写作基因 3～5 条**：至少由两个维度共同支撑、删掉就不像了的特征。每条 4～6 字的名字 + 一句话说明它由哪几个维度撑起来。
2. **铁律 6～10 条**：落到操作层，写完回头看一眼就能判断有没有做到。反例：「要生动」。正例：「每段至少一个可以摸到的物件」。
3. **禁用清单 5～10 条**：这段文字**从不做**的事，具体到句式、词、动作。这一项比正面特征更能定边界。
4. **AI 腔词表**：这批文字里根本不会出现的套话（「不由得」「心中五味杂陈」「一丝不易察觉」这类），最多 20 个。
5. **指纹小结**：300 字以内，一口气说清这副笔调是什么样。
6. **起笔口诀**：30 字以内，一句能默念的话。

### 四、存卡

用 `style_card_save` 存进库，`library` 传库名或 id。存完核对返回的 `counts`：维度数、基因数、铁律数、禁用数、AI 腔数，缺项就补。

**这一步卡还没生效。** 要让它在每轮正文里起作用，得把库的注入方式设成 `both`（摘录＋卡）或 `card`（只用卡）：

```
style_library_save { name: "库名", id: "库 id", tags: [...], mode: "both" }
```

注意 `style_library_save` 会覆盖 tags 和 note，所以要先把库里原有的 tags 读出来、原样带回去。改完告诉用户当前是哪种注入方式。

### 五、盲测（用户要求「验一下」时做）

让用户自己看比让模型自评更可靠。做法：

1. 用 `style_library_list` 找到库，让用户挑一段**没参与分析**的原文。
2. 你按卡写 200～300 字，不给原文。
3. 把两段并排给用户，问他哪段更像，差在哪。
4. 差得多就回到第三步修卡，别改摘录。

面板上也有「试写一段」按钮，走的是同一件事（按卡写，再让模型自评一个百分比），结果会存进卡的 `match` 字段。

## 和建库的分工

| | `create-style-library` | `distill-style-library`（本 Skill） |
| --- | --- | --- |
| 输入 | 用户引用的整本书 | 库里已有的摘录 |
| 产出 | 一个库 + 几十条逐字摘录 | 一张风格卡 |
| 什么时候 | 空库 | 库里已经有 5 条以上 |

先建库、再提炼。顺序反了就没有材料。

## 边界

- 库里摘录少于 3 条：不要硬提炼，说清楚为什么（样本不够会把即兴当风格）。
- 用户的判断和你冲突时听用户的。他说这段算「絮语」就按絮语写，标签是他的分类习惯。
- 不要把摘录原文抄进卡里。卡写的是规则和观察，抄原文既占容量也可能被模型直接复述。
- 卡的上限是 24 KB。顶到上限说明塞了太多废话，删条目，不是拆库。
